---
version: "4.1.1"
date: "2026-08-29"
title: "Every outbound integration call now has a time limit"
summary: "ClickUp, Google Calendar, Google Places, Google sign-in, reCAPTCHA, the PLUS update and attachment downloads all moved onto the shared client introduced in the previous release. No server-side call can now hang without limit, and a check keeps it that way."
fixed:
  - title: "ClickUp calls give up rather than hanging"
    detail: "Creating a task, uploading an attachment, and reading task or field data are all bounded now — ten seconds for ordinary calls and twenty for attachment uploads, which carry a file. Reads are retried up to three times, because the daily sync makes one call per ticket and a single blip would otherwise silently drop that ticket from the run. Task creation and attachment uploads are never retried, so a slow response cannot produce a duplicate."
  - title: "Attachment downloads are limited by size as well as time"
    detail: "Copying an attachment onto a ClickUp task downloaded it with no time limit and no size limit, reading the whole file into memory. It now times out after twenty seconds and refuses anything above the same ten megabyte ceiling the upload path enforces, checked both before and after the download since a declared size cannot be trusted."
  - title: "Google and reCAPTCHA calls are bounded"
    detail: "Sign-in, calendar sync, place lookup and reCAPTCHA verification are all limited now. None of the single-use exchanges are retried — an authorisation code or a verification token can only be used once, so a second attempt would be rejected even when the first merely timed out. Calendar event syncs are likewise never retried, because a duplicate event is worse than a sync the system already reports as failed."
  - title: "PLUS update calls to the POS no longer hang a run"
    detail: "The two updates the PLUS job makes per row are limited to fifteen seconds and retried once. Retrying is safe here specifically because each sets a value outright rather than adjusting one, so repeating it lands on the same result."
improved:
  - title: "A check stops this from creeping back"
    detail: "The pipeline now fails if any server-side code calls out to the network without going through the shared client, so a future change cannot reintroduce an unbounded call by accident."
---
