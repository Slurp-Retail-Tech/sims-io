title: "Merchant import logging no longer risks writing a token to the logs"
summary: "Two diagnostic messages in the merchant import moved onto the structured logger, and the addresses they record are now trimmed so a POS access token cannot end up in the log output."
security:
  - title: "POS addresses are trimmed before being logged"
    detail: "When the POS system rejected an import, the diagnostic message recorded the full address of the request, including anything after the question mark. One of the ways the application talks to the POS system puts the access token there, so that message could have written a working token into the logs. Addresses are now recorded without that portion."
improved:
  - title: "Import diagnostics use the structured logger"
    detail: "The two remaining free-form diagnostic messages in the merchant import now go through the shared logger, so they carry the same searchable fields and request identifier as everything else."
