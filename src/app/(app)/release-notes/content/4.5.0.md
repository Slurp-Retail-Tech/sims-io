---
version: "4.5.0"
date: "2026-08-29"
title: "Configuration mistakes are caught at startup, not hours later"
summary: "All 96 settings the application reads are now declared in one place. A production instance missing any of them refuses to start and says which ones and why, instead of starting successfully and failing later when someone uses the affected feature."
new:
  - title: "Every setting is declared, and checked at startup"
    detail: "Settings are now classified as always required, required in production, required only when the feature they belong to is switched on, or one-of-a-choice. A production instance missing anything required refuses to start and lists every missing setting together with a short explanation of what breaks without it — so the fix is a single pass rather than one restart per missing value."
  - title: "A half-configured integration is treated as a mistake"
    detail: "Integration settings are only demanded once that integration is switched on. Leaving ClickUp or Google Calendar entirely unconfigured is fine; configuring one halfway is now reported at startup rather than failing at the moment someone uses it."
fixed:
  - title: "Public settings can now actually reach the browser"
    detail: "Eight of the ten browser-visible settings — including the analytics, pixel and support-contact values — could never be included in the application bundle, because the container build had no declaration to receive them. They were documented as configurable and would have appeared set on the platform while having no effect. All ten are now wired through, and a check keeps the list complete."
improved:
  - title: "Configuration files cannot drift apart"
    detail: "The pipeline now fails if a setting is read in code but undeclared, declared but missing from the example configuration file, or present there but unknown to the code."
