date: "2026-08-29"
title: "ClickUp sync and CSAT links write atomically"
summary: "ClickUp status syncs and both CSAT survey-link paths now commit their changes and audit entries together. A survey link can no longer end up with every token consumed and none usable, and sharing a link no longer depends on a status that may already have changed."
fixed:
  - title: "A CSAT survey link can no longer be issued into a broken state"
    detail: "Issuing a survey link marks any previous token for the ticket as used and then creates a replacement. Those were two separate statements, so an interruption between them left the ticket with every token consumed and no working link — and no way to send one without manual database work. They now commit together, on both the automatic send when a ticket closes and the manual share button."
  - title: "Sharing a survey link re-checks the ticket is still resolved"
    detail: "The manual share button read the ticket's status, then did its work. If someone reopened the ticket in between, the link was still shared. The status is now held for the duration of the operation."
  - title: "ClickUp status syncs record what they actually replaced"
    detail: "Syncing a ticket's ClickUp status read the current values, worked out what changed, then wrote the update and one audit entry per changed field as separate statements. A concurrent edit could make those entries describe values that had already been replaced, and an interruption could apply the update with only some of its history. Each ticket now syncs as a single unit. The ClickUp API call stays outside it, so a slow response cannot hold a database lock."
improved:
  - title: "Audit entries are written in one round trip"
    detail: "A ClickUp sync touching three fields previously issued three separate audit writes. All entries for one change now go in together."
