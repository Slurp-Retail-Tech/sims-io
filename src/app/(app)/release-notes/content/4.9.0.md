title: "PLUS updates resume where they stopped"
summary: "A PLUS update now works through the spreadsheet in short stretches, saving its position as it goes, so a deployment or restart part-way through picks up from the last completed row instead of leaving the run stuck."
fixed:
  - title: "An interrupted update resumes from the last completed row"
    detail: "The update ran detached from the page that started it, with nothing supervising it. If the application restarted mid-run, the job stayed marked as running forever, the page waited on it indefinitely, and there was no way to resume or clear it. It now advances in short stretches that record their position, and an interrupted run is picked up automatically."
  - title: "A resumed run checks it is reading the same file"
    detail: "The saved position is an offset into the uploaded spreadsheet, so resuming against a different file would process the wrong rows. The file's contents are fingerprinted when the run starts and checked on resume; a mismatch stops the run and asks for a re-upload rather than guessing."
  - title: "The progress page can no longer wait forever"
    detail: "The page polled for completion with no limit, so a stalled run left the tab spinning indefinitely. It now gives up after a bounded period and tells you the run continues in the background."
improved:
  - title: "The page helps the update along while it is open"
    detail: "Watching the progress page now actively advances the run, so an update finishes faster while someone is looking at it. Closing the page no longer strands it — the scheduled runner continues the work."
  - title: "Spreadsheet reading is covered by tests"
    detail: "The rules for reading the template — where data begins, how repeated entries are treated, and how blank rows are handled — had no tests despite depending on a fixed row offset that a template change would silently shift. They are now covered."
