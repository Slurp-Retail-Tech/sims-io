title: "Faster, steadier merchant import"
summary: "The merchant import now saves each page of merchants in a few database steps instead of more than a thousand, and a slow response from the POS system no longer makes it retry work it was still doing."
fixed:
  - title: "A slow POS response no longer wastes import retries"
    detail: "If the POS system was slow to answer, the import could take longer on one page than it was allowed. It was then treated as stuck and restarted while still running, using up one of its retries each time. A slow POS alone could make an import give up. Fetching a page now has a firm time limit. If the limit is hit after other pages have already been imported, the page is picked up again shortly without using a retry."
improved:
  - title: "Merchant import saves pages much faster"
    detail: "Each page of 100 merchants used to be saved one merchant and one outlet at a time: about 1,100 database steps for a typical page. It now takes three. A record that can't be saved is still skipped and reported on its own, as before."
