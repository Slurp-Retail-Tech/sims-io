date: "2026-08-29"
title: "Optional error tracking"
summary: "Server and browser errors can now be reported to Sentry. It is entirely opt-in: without an account configured, nothing is loaded, nothing is sent, and the build is unchanged."
new:
  - title: "Error tracking, off by default"
    detail: "Providing a Sentry address turns on error reporting for both server and browser errors, tagged with the running version so a spike can be traced to a specific release. Leaving it unset costs nothing: the reporting library is never loaded at runtime and the build step that uploads debugging symbols is not applied. This was confirmed by inspecting a running production build with no address configured."
  - title: "Personal information is never collected"
    detail: "Reporting is configured to exclude request contents, headers, cookies and user identifiers. Given the merchant contact details and support conversations this system handles, that is a deliberate setting rather than a default, and error reports carry only the error itself and where it happened."
