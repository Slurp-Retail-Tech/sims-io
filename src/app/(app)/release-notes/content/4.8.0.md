version: "4.8.0"
date: "2026-08-29"
title: "A failed PLUS update can now be retried"
summary: "A PLUS update that failed deleted the spreadsheet it was working from, so there was nothing left to retry. The file is now kept, each row records exactly which changes reached the POS system, and a run that stops halfway can be re-run without redoing the parts that already succeeded."
fixed:
  - title: "A failed run no longer destroys its own source file"
    detail: "The uploaded spreadsheet was deleted on every exit from the update, including failure — and the update reads that same file to start, so a failed run could not be retried at all. The file is now kept for three days after the run finishes and removed automatically afterwards. Closing the page during a run can no longer delete it either."
  - title: "A row that half-succeeded is reported as such"
    detail: "Each row can make two separate changes in the POS system. If the first succeeded and the second failed, the whole row was reported as failed — even though half of it was already live — and the previous values were not recorded anywhere. Each change is now recorded independently along with the value it replaced, and such a row is reported as partially updated. Re-running sends only the change that did not go through."
  - title: "Long updates no longer fail once the POS session expires"
    detail: "The update signed in to the POS system once before starting and used that session for every row. A long run outlived it, after which every remaining row failed with an unhelpful error. The session is now renewed as needed."
improved:
  - title: "A large update does far less database work"
    detail: "Each row re-fetched merchant details the update had already loaded for every row before starting — one query per row. A three thousand row spreadsheet now does that once instead of three thousand times."
  - title: "Local records are updated once per row"
    detail: "The local copy of merchant details was written once per change, in two statements each, with nothing tying them together. Each row now updates it once, as a single unit."
