version: "4.15.0"
date: "2026-09-15"
title: "Seeing the renewal pipeline"
summary: "Two new screens under Renewal & Retention: the invoices raised by the nightly run, and the queue of everything stopping one being raised. The data existed as of the last release; this is where it becomes workable."
new:
  - title: "An invoice list, and an invoice that explains itself"
    detail: "Every proforma the nightly run raises now appears in a list filterable by status, with the merchant, the amount, the due date and the chosen term. Opening one shows each outlet being billed, the list price beside the price actually charged, and where any difference came from, so an amount can be accounted for without recalculating it."
  - title: "A timeline on every invoice"
    detail: "Each invoice carries a record of everything that has happened to it, in order, including which steps were automatic. When a merchant asks why they received what they received, the answer is on the page rather than in a log."
  - title: "The Actions Required queue"
    detail: "Everything blocking a renewal now has a screen, sorted by how long is left before the licence expires rather than by how long the problem has existed. Each entry says in plain terms what is wrong and what would fix it. Entries that only need recording, rather than acting on, are kept separate from the ones actually stopping an invoice."
  - title: "Entries clear themselves"
    detail: "Nothing in the queue needs ticking off. Assign the missing plan or name the missing contact, and the next nightly run both clears the entry and invoices the outlet. Dismissal is reserved for an entry that genuinely is not a problem, and it asks why so the record explains itself."
improved:
  - title: "An invoice's existence is not revealed to someone who cannot see it"
    detail: "Requesting an invoice without permission returns the same response as requesting one that does not exist, so the addresses cannot be probed to learn which invoices are real. This matches how the Project Tracker already behaves."
fixed:
  - title: "A single-outlet invoice is no longer labelled as grouped"
    detail: "A franchise set to be billed as a group, but with only one outlet expiring on a given date, produced an invoice marked as grouped while billing one outlet. It is now labelled by what it actually bills."
