title: "Groundwork for imports that survive a deployment"
summary: "New machinery for long-running work — imports and syncs — so a job can be paused, resumed and recovered instead of being lost when the application restarts. Nothing uses it yet; the imports move across in the next releases."
new:
  - title: "A durable record for long-running jobs"
    detail: "Long-running work now has somewhere to record what it is doing: what it has processed, where to resume from, how many attempts it has had, and a per-item record of what happened to each row it touched. Work proceeds in short slices that save their position, so a job interrupted by a deployment resumes from where it stopped rather than starting over or being abandoned."
  - title: "Only one copy of a job can run at a time"
    detail: "Each kind of job takes an exclusive claim while it works, so a scheduled run and someone pressing a button at the same moment cannot both process the same data. The claim is released automatically if the application stops, so a restart mid-job frees it immediately rather than blocking the next run."
  - title: "Abandoned jobs are recovered automatically"
    detail: "A job whose claim expires — because the application restarted while it was running — is picked up again on the next cycle, up to a retry limit, after which it is marked failed. Previously such a job stayed marked as running forever, with nothing to notice or recover it."
