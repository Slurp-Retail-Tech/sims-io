version: "4.40.1"
date: "2026-10-08"
title: "Merchant import no longer stalls on one bad record"
summary: "A single malformed merchant record from the POS system could stop every merchant import at the same point, and the reason never reached the Merchants page. Bad records are now skipped and reported, and the real cause of a failed import is shown."
fixed:
  - title: "One bad record no longer blocks the merchant import"
    detail: "A merchant or outlet with an unusually long or malformed field used to fail its whole page of results. Every retry and every later import stopped at the same place, so merchants after it were never refreshed. These records are now skipped and listed individually, and the import carries on. If more than 5% of merchants are rejected, the import is marked as failed so the problem gets noticed."
  - title: "Failed imports now show why they failed"
    detail: "The Merchants page used to show only a generic lease-expired message for a failed import. It now shows the actual cause, such as the error the POS system returned, and imports that finished with skipped records say how many."
  - title: "Starting an import no longer reports a false failure"
    detail: "If the first batch hit an error, the Import button reported that the import had failed, even though it was queued and would retry. It now reports that the import has started, and the status shown on the page tracks the retries."
  - title: "Credentials are removed from import error messages"
    detail: "Error text returned by the POS system is now shortened, and any access tokens are removed before it is logged or shown on the page."
