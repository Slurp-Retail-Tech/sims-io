version: "3.5.0"
date: "2026-08-29"
title: "Groundwork for atomic ticket writes"
summary: "A shared transaction helper and a single ticket-history writer now exist in the shared library, replacing a helper that lived inside one API route folder and nine hand-written history INSERTs. Nothing changes for users yet — this is the foundation the next release builds on."
new:
  - title: "One transaction helper for the whole codebase"
    detail: "withTransaction now lives alongside the database pool instead of inside the contacts API route folder, so any part of the server can run several statements as one all-or-nothing unit. It also no longer lets a failing rollback hide the error that caused it, which previously sent anyone reading the logs to the wrong place."
  - title: "A single writer for ticket history"
    detail: "Ticket history rows were being inserted from nine different places, each with its own hand-written statement. There is now one shared writer that all of them can use, and it records every changed field in a single database round trip rather than one per field."
improved:
  - title: "The PLUS update page no longer creates a table on every status check"
    detail: "While a PLUS update runs, the page checks its progress every 1.5 seconds. Each of those checks was also issuing a redundant table-creation statement. The check now reads progress only, which removes that traffic for every person watching a run."
