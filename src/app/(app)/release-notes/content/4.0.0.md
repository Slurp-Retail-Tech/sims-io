version: "4.0.0"
date: "2026-08-29"
title: "Editing a ticket is now a single all-or-nothing change"
summary: "Saving a ticket wrote the ticket, its history entries and any confirmed outlet link as separate steps. Two people editing the same ticket at once could produce history entries describing values that had already been replaced. The whole save is now one unit."
breaking_changes:
  - title: "A confirmed outlet link that fails now fails the save"
    detail: "When an agent confirms an outlet on a flagged ticket, that choice is saved to the contact directory so the next ticket from the same contact links automatically. Previously, if writing it failed, the error was logged and the save still reported success — the agent had no idea their confirmation was lost. It is now part of the same save, so a failure returns an error instead of a false success. Retrying is safe: nothing is applied unless everything is. Anything calling the ticket update endpoint directly should expect an error response in this case where it previously received a success."
fixed:
  - title: "Concurrent edits no longer corrupt ticket history"
    detail: "Saving a ticket read its current values, worked out what changed, then wrote the update and one history entry per changed field. Nothing held the ticket between the read and the write, so two agents saving at once could each compare against an out-of-date snapshot and both record a change from a value the other had already replaced. The ticket is now held for the duration of the save, so each entry records what it genuinely replaced."
  - title: "A ticket can no longer be updated without its history"
    detail: "The ticket update and its history entries were separate statements on separate connections. An interruption between them left a changed ticket with an incomplete or missing audit trail. They now commit together, in a single round trip rather than one write per changed field."
improved:
  - title: "The survey link on close still cannot block a save"
    detail: "Closing a ticket sends the satisfaction survey link. That send stays outside the save, so a slow or unavailable messaging service cannot hold up the close or hold a database lock. Its outcome is still reported back so the interface can show whether the survey went out."
