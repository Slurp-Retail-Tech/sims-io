version: "4.1.0"
date: "2026-08-29"
title: "Outbound calls can no longer hang indefinitely"
summary: "A shared HTTP client gives every outbound integration call a time limit, optional retries and consistent handling. The POS API, email and file storage adopt it first — previously an unresponsive service could hold a request or an import open with no limit at all."
new:
  - title: "A shared client for every outbound call"
    detail: "All outbound requests to ClickUp, the POS API, Google and the rest previously used the platform's raw request function, which has no time limit by default. Only two of twenty-three call sites set one. There is now a single shared client with a per-call time limit, optional retries with a randomised backoff, and a rule that a request which could change data is never retried automatically."
fixed:
  - title: "POS API calls now give up rather than hanging"
    detail: "Every POS call now has a 30 second ceiling, and signing in has a 10 second one. Because the merchant import and the PLUS update walk many pages or rows one after another, a single unresponsive page could previously stall an entire run with nothing to break the wait."
  - title: "Email sending has connection and socket limits"
    detail: "Sending mail relied on the operating system's own timeouts, so a mail server that accepted a connection and then went quiet could hold a request open for minutes. Connection, greeting and socket limits are now set explicitly, and connections are pooled and reused instead of opened per message."
  - title: "File storage calls have their own limits"
    detail: "Uploads and downloads now fail fast if storage cannot be reached within three seconds, and no single file operation may run longer than thirty."
improved:
  - title: "Three copies of the POS fallback became one"
    detail: "Some POS endpoints reject the standard authorisation header and only accept the token another way, so calls try one form and fall back to the other. That fallback was written out three times in near-identical form. It is now a single implementation, which also means the time limits apply uniformly."
