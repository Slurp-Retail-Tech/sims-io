version: "4.7.0"
date: "2026-08-29"
title: "Merchant import and ClickUp sync survive a deployment"
summary: "Both scheduled jobs now run in resumable slices instead of one long request. A deployment part-way through no longer loses the run, and two runs can no longer overlap."
breaking_changes:
  - title: "Starting an import returns immediately instead of waiting"
    detail: "The merchant import used to run entirely within the request that triggered it, so the caller waited for every page of the POS feed. It now records the work to be done, does a first slice, and returns straight away — the button reports \"Import started\" rather than \"Import completed\", and the existing progress indicator reports actual completion. Anything calling the import endpoint directly should treat its response as an acknowledgement and poll the status endpoint, rather than reading it as a finished import."
fixed:
  - title: "An interrupted import resumes instead of starting over"
    detail: "The import walks the POS feed one page at a time and records its position after each. A deployment or restart part-way through now resumes from the last completed page. Previously the run was marked failed with no record of how far it got, and re-running started again from the first page."
  - title: "The ClickUp sync no longer processes every ticket in one request"
    detail: "The daily sync read every linked ticket at once and then made one call to ClickUp per ticket, all inside a single request, which grew unbounded with the number of tickets. It now works through them in batches, saving its position between them."
  - title: "Two runs of the same job can no longer overlap"
    detail: "Nothing previously stopped the scheduled run and a manual trigger from processing the same data simultaneously. Each job now takes an exclusive claim, so a second trigger joins the run already in progress instead of starting a competing one."
  - title: "The import can no longer loop indefinitely"
    detail: "The import continued as long as the POS feed kept returning full pages, with no upper bound. There is now a page ceiling, and reaching it reports a failure rather than quietly stopping — a short import that claims success is worse than one that says it stopped early."
